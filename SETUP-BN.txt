ARiYAN - Backend setup (Render)
==============================

এই আপডেটে যোগ হয়েছে:
- Email registration/login API (password hashed with scrypt)
- Customer profile and wallet balance API
- Manual bKash/Nagad deposit request with Transaction ID
- Admin-only deposit approval/rejection; balance is credited only after approval
- Wallet-funded order API; server verifies package and price against website configuration
- Customer order/transaction history API
- Admin-only user/deposit/order list and order status/refund API

Render Environment Variables:
- FFX-PASS = আপনার শক্তিশালী Admin password (আগের Admin Panel-এর জন্যও)
- BKASH_NUMBER = আপনার bKash receive number (ঐচ্ছিক; customer payment info endpoint-এ দেখায়)
- NAGAD_NUMBER = আপনার Nagad receive number (ঐচ্ছিক)
- DATA_DIR = Render Persistent Disk mount path, যেমন /var/data
- GOOGLE_CLIENT_ID = Google Cloud Console থেকে তৈরি OAuth 2.0 Web Client ID (Google Login চালু করতে আবশ্যক)

IMPORTANT - Render storage:
Render instance-এর local filesystem deploy/restart-এ হারিয়ে যেতে পারে। Render Dashboard-এ Persistent Disk যোগ করে Mount Path `/var/data` দিন এবং `DATA_DIR=/var/data` সেট করুন। এই Persistent Disk না থাকলে customer database হারাতে পারে। Scale to multiple instances করলে JSON-file storage ব্যবহার করবেন না; managed database দরকার।

API endpoints:
POST /api/auth/register {name,email,password}
POST /api/auth/login {email,password}
GET  /api/customer/me                 Authorization: Bearer <customer token>
GET  /api/customer/orders             Authorization: Bearer <customer token>
GET  /api/customer/transactions       Authorization: Bearer <customer token>
POST /api/customer/deposits {amount,method:"bKash"|"Nagad",trxId}
POST /api/customer/orders {product:<key>,packageName,price,playerId,server}
GET  /api/payment-info

Admin endpoints (use existing Admin Panel token):
GET  /api/admin/users
GET  /api/admin/deposits
GET  /api/admin/orders
POST /api/admin/deposit-action {id,action:"approve"|"reject"}
POST /api/admin/order-action {id,action:"processing"|"delivered"|"rejected"}

গ্রাহক পেমেন্ট জমা দেওয়ার সময় শুধু bKash/Nagad মাধ্যম, টাকার পরিমাণ এবং Transaction ID দেবেন। স্ক্রিনশট আপলোডের কোনো ফিল্ড নেই। Admin নিজের bKash/Nagad অ্যাকাউন্টে টাকা ও TrxID মিলিয়ে তারপর Approve করবেন।

Manual payment safety:
Never approve a deposit based only on a screenshot. Verify the actual incoming payment and amount in your bKash/Nagad account before approving. Transaction IDs are checked for duplicates per payment method.

NOTE:
এই আপডেটে backend API যুক্ত ও smoke-tested হয়েছে। বর্তমান FFX.html-এর পুরনো hard-coded isLoggedIn=false এবং product purchase UI-গুলো এখনো নতুন API-তে সম্পূর্ণভাবে সংযুক্ত করা হয়নি। তাই ZIP deploy করলেই পুরো customer-facing login/deposit/order UI স্বয়ংক্রিয়ভাবে চালু হয়েছে ধরে নেবেন না। পরের ধাপে ওই UI এবং Admin Panel-এর Orders/Deposits screens সংযুক্ত করতে হবে।

Frontend connection added:
- customer.js connects the existing site account/login, Add Money, Wallet and product purchase buttons to the APIs.
- Admin Panel now has an Orders & Payments section for deposits, orders and customer list.
- Purchases use Wallet Pay only. Direct/Instant Pay is hidden because no gateway is configured.
- My Codes remains a placeholder because no redeem-code feature existed in the original project.

Before deploying:
1. Back up any existing Render persistent data and current environment settings. Do not delete the existing disk or data folder.
2. Keep the existing FFX-PASS value unchanged; it protects the existing Admin Panel.
3. Add a Render Persistent Disk (mount path /var/data) and set DATA_DIR=/var/data. If the existing site already has a data folder, migrate/copy it to the disk before switching DATA_DIR, otherwise the old site customizations may not appear.
4. Set BKASH_NUMBER and NAGAD_NUMBER to the correct receiving numbers. Do not put private API keys in frontend files.
5. Deploy one instance only when using the JSON customer database. For multi-instance production use a managed database.
6. Test a small deposit first. Admin must verify the actual incoming payment in the bKash/Nagad account before approval.


Google Login চালু করার ধাপ:
1. https://console.cloud.google.com/ খুলে একটি Google Cloud Project তৈরি করুন।
2. Google Auth Platform / OAuth consent screen-এ App name, support email এবং প্রয়োজনীয় তথ্য দিন।
3. Audience/Publishing status সেট করুন; Testing mode হলে যেসব Google account দিয়ে পরীক্ষা করবেন সেগুলো Test users-এ যোগ করুন।
4. Clients থেকে OAuth Client তৈরি করুন: Application type = Web application।
5. Authorized JavaScript origins-এ আপনার Render সাইটের মূল HTTPS origin দিন, যেমন https://আপনার-সাইট.onrender.com (কোনো path দেবেন না)।
6. তৈরি হওয়া Client ID Render Environment-এ GOOGLE_CLIENT_ID নামে বসান। Client Secret এই কোডে লাগবে না; frontend-এ দেবেন না।
7. Render-এ Save করে নতুন Deploy দিন। Google দিয়ে একই verified email ব্যবহার করলে আগের account-এর wallet ও order history অক্ষত থাকবে।

নিরাপত্তা:
- Google ID token সার্ভারে Google-এর tokeninfo endpoint দিয়ে যাচাই করা হয়।
- Google Client ID অবশ্যই আপনার নিজের OAuth Web Client ID হতে হবে।
- কোড প্রস্তুত; Render-এ GOOGLE_CLIENT_ID না বসানো পর্যন্ত Google Login চালু হবে না।


নতুন ARiYAN Delivery Management প্রস্তুতি:
- নতুন Order-এ deliveryMethod='unassigned' থাকবে।
- Admin Orders & Payments থেকে চলমান Order-কে Manual Delivery হিসেবে নির্বাচন করতে পারবেন।
- API delivery ইচ্ছাকৃতভাবে চালু করা হয়নি; Supplier-এর প্রকৃত API Documentation, অনুমোদিত API credentials, product mapping, status codes এবং refund rules না জেনে live order পাঠানো নিরাপদ নয়।
- Admin-only GET /api/admin/suppliers endpoint SUPPLIER_1_NAME ... SUPPLIER_5_NAME এবং সংশ্লিষ্ট SUPPLIER_n_API_KEY আছে কি না দেখায়; কোনো secret ফেরত দেয় না।
- ভবিষ্যতে Render Environment Variables-এ SUPPLIER_1_NAME, SUPPLIER_1_API_KEY; দ্বিতীয় Supplier-এর জন্য SUPPLIER_2_NAME, SUPPLIER_2_API_KEY ইত্যাদি রাখা যাবে। API URL/auth format supplier documentation অনুযায়ী নির্ধারণ করতে হবে।
- API timeout বা uncertain response হলে স্বয়ংক্রিয় refund করবেন না; supplier order status যাচাই করে তারপর admin action নিতে হবে।
- Deploy-এর আগে customers.json এবং বর্তমান Render Environment Variables-এর backup নিন। পুরোনো FFX-PASS, BKASH_NUMBER, NAGAD_NUMBER ও DATA_DIR অপরিবর্তিত রাখুন।
